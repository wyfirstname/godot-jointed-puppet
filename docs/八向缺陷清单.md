# 八向的缺陷清单：为什么「5 张图 + 镜像」不可能干净

> 结论先行：**八向不是「画 8 张图」，是 8 次空间关系重算。**
> 5 视图 + 3 镜像省掉 37.5% 的画量，代价是三类系统性错误会渗进每一个槽位：
> 镜像只翻屏幕左右、不翻深度；一套 z 表要服务 8 个方向；二维平面只有一个旋转轴。
>
> 本文是逐槽位的核对结果。**已修**的部分有代码和可复跑的检查（`tools/zdump.gd`），
> **未修**的部分写清了原因和代价，不装作不存在。

## 1. 依据

### 1.1 引擎文档（Godot 4.7，本机对应版本）

| 事实 | 出处 | 对我们的影响 |
|---|---|---|
| **负 X 缩放不可分解**：「negative scales on the X axis will be changed to negative scales on the Y axis and a rotation of 180 degrees when decomposed」 | `class_node2d.html` | 不能靠读 `scale.x < 0` 判断朝向；判断朝向只能看变换矩阵（`get_transform().x.x`） |
| `z_index` 必须在 `CANVAS_ITEM_Z_MIN..MAX`；`z_as_relative` 默认 `true`（子节点 z 叠加父节点） | `class_canvasitem.html` | 我们全部用 `z_as_relative = false`，让每个槽位的 z 是绝对值，不被关节层级污染 |
| **Y 排序只在同 `z_index` 之间生效**：「Nodes sort relative to each other only if they are on the same z_index」 | `class_canvasitem.html` | 多角色同屏靠 `z_base` 分层，不能指望 y_sort 混着 z_index 用 |
| `Sprite2D.flip_h` 只翻转贴图，不改变节点的枢轴 | `class_sprite2d.html` | v2 曾逐图层 `flip_h`，结果贴图翻了、枢轴没翻 → 全身错位。改整只 `scale.x = -1` |
| `Bone2D.rest` 是**相对父骨骼**的变换；`apply_rest()` 才能复位 | `class_bone2d.html` | 骨骼方案里改一个 rest 会连带所有子骨骼，运行时逐帧改 `transform` 更可控 |
| `Skeleton2D` 只在需要 `Polygon2D` 蒙皮变形 / IK 时才有价值 | `class_skeleton2d.html` | 本方案不蒙皮、不 IK，所以**完全不用 Skeleton2D** |

> 补充一条工程事实（Godot issue #75224）：**2D IK 在父节点负 X 缩放下会失效**。
> 这条是我们坚持「镜像在整只人偶根节点上做、而不是在骨架内做」的另一个理由：
> 一旦哪天要接 IK，镜像位置还能整体挪到外面那一层去。

|---|---|---|

## 2. 三条系统性缺陷（所有槽位问题的根）

### A. 镜像翻的是屏幕左右，不是深度

`scale.x = -1` 之后：**哪条腿在前、哪只胳膊离镜头近，完全不变**。
但人绕着镜头转的时候，远近是会换的。

所以「近侧肢体压在躯干上、远侧沉到躯干后」这件事，**只对一半方向成立**。
我们之前的 z 表是一套固定值，转身到背面 3/4（NW/NE）时：
近侧那条胳膊仍是 8（沉在躯干 10 后面）→ 走路时胳膊在胸口忽隐忽现。

**修法**：四肢的 z 拆成「近侧 / 远侧」两套，按**视图**（不是方向）查表。
镜像不改变远近，所以 NE 和 NW 用同一套；E 和 W 用同一套。

### B. 一套 z 表服务 8 个方向，必然有方向是错的

披风在正面是「在身后」（z=2），在背面是「在身上」（z=22）。
后发在正面是「在头后」（z=0），在背面是「在头前」（z=31，盖住 `head` 30）。
刘海、五官在背面必须沉底。

**修法**：`Z_ON_BACK` 逐方向覆盖表，优先级高于默认表。这不是补丁，是这类系统的必要结构
——参考视频作者原话就是「每个方向，都单独排一遍图层」。

### C. 二维平面只有一个旋转轴

关节只能绕屏幕法线转。所以：

- **点头做不出来**。头一转，在屏幕上就是「歪头」。正面走路时如果给头加反向扭，看起来像落枕
  —— 已改成正面/背面不做上半身扭动（`sway = 0` when `mode == 1`）。
- **正面摆臂看着像扑腾**。手臂前后摆是景深方向的运动，投到屏幕上只剩一点点横向位移。
  正面用侧视的 18° 摆幅 = 手在身体两侧扇风 —— 已把 S/N 的摆幅压到 4°。
- **弹簧只会左右摆**。角色朝镜头走时，披风真正动的是前后（景深），
  屏幕上不该左右甩 —— 已加按视图的 `SPRING_GAIN`（正/背面 0.25，侧面 1.0）。

| 项 | 问题 | 状态 |

### 5.3 披风的角度与背面双臂（2026-11 补）

用户报的两个现象：「斜角角色的披风都有角度问题」「内部的手臂摆动方向应该在身前，
现在有的在身后」。查下来是两个不相干的错，但都落在同一张 z 矩阵里。

**一、披风是圆弧，不是平板。** 判据：绕躯干竖直轴转 θ 后，布的**投影宽度**应该是多少。

平板模型给 `W·|cosθ|`，90° 时塌成零宽；真实的布是包在背上的一段弧，永远有厚度。
按半径 `r`、半包角 `φ` 的弧，取 `α ∈ [−φ, φ]` 的极值就是左右边界：

```
x(α) = r·sin(α + θ)   →   xmin/xmax = r·min/max{sin(α+θ)}
```

取 `φ=75°`、上沿 `r=17`、下摆 `r=29`，五视图落点：

```
视图  上沿 x 区间      下摆 x 区间       旧平板公式
S     111.6–144.4      100.0–156.0       几乎相同（θ=0 无差别）
SW    119.5–145.0      113.5–157.0       左缘外溢到 112
W     132.4–145.0      135.5–157.0       左缘 116 ← 越过中线 128，布绕到正面
NW    119.5–145.0      113.5–157.0       同 SW
N     111.6–144.4      100.0–156.0       同 S
```

两处病：①宽度收不够，W 那格左缘到 116，比中线 128 还靠左 —— 布绕到人的**正面**，
读起来是围裙；②上沿移 `shift`、下摆只移 `shift·0.5`，整块布被"拧了一下"，
这就是「角度不对」的直接来源。现在上下沿各自求投影区间，布褶线走**可见段**中线。

对照图：`docs/cape_wrap_compare.png`。

**二、背面的远侧胳膊沉在披风后面。** 背面披风 z=22，近臂 24 压过它，
远臂却还是 `LIMB_Z` 的 8 —— 落在布的下面。NW 那格披风覆盖 x 119–144，
远臂 `arm_r` 占 138–155，**内半边被红布吃掉**，而且随摆臂周期性被整条吞掉：

```
往后摆（屏幕右）→ 钻出布外    往前摆（屏幕左）→ 整条钻进布里
```

NW/NE 两格只剩一把剑浮在半空。这不是「远近算错侧」，是把它和披风摆在了错误的相对位置 ——
没有任何一条胳膊是裹在布里面的，两条都该在布前面。

改成 `ARM_Z_ON_BACK = {near: 24, far: 23}`（前臂 25/24），远侧只低一档保留层次。
`zdump.gd` 的背面断言从「只看近臂」改成 `for side in ["l","r"]` 两条都 > 披风，
再加一条 `znear >= zfar`。

对照图：`docs/nw_arm_compare.png`（v1 状态的对照，现作历史记录）。

**后续反转（用户拍板）。** v1 的胳膊确实不再消失了，但背面看起来像胳膊**贴在
红布外面**，两颗金肩球像钉在披风上的扣子。披风既然裹住整个后背，胳膊垂在身侧
本来就该被布挡住 —— 于是 v2 把整条手臂连肩球一起压到 21/20（仍在躯干 10 之前），
SW 的远臂整条沉到披风(2)之下（1/1/1）。`zdump` 断言同步反转：
背面 `双臂 < 披风`、`肩球 < 披风`、`近臂 > 躯干`，另加 `dir=1 远臂 < 披风`。

两个有意识的副作用：

1. **背面视图里手臂完全看不见**（被布盖住）。这是「披风裹身」外观的一部分，不是 bug；
2. **武器（weapon 50）仍在布外** —— 手藏起来了、剑还浮着。要不要把武器也收进布里，
   在 `layer_rules.json` 里把 `weapon` 调到 21 以下即可，设计器里改一格立刻能看效果。

**三、为什么这次能一次改对。** 因为把结果矩阵从五张互相引用的表里搬了出来：

```bash
--headless --script res://tools/dump_layers.gd   # 从推导生成 data/layer_rules.json
# 改一格想试效果，直接开 tools/layer_designer.html 拖，或者手改 JSON
--headless --script res://tools/zdump.gd         # 用运行时读到的 z 复核不变量
```

改 JSON 立刻生效的实测（把 S 的披风临时改成 20）：

```
dir=0 正面披风跑到身体前面：20 >= 10     ← 退出码 1，验完还原为 2
```

**四、时间维度。** 静态矩阵表达不了「同一条手臂摆到前面该压躯干、摆回去该沉后面」。
`layer_rules.json` 的 `swing` 数组按关节角 + 迟滞实时切。实测（临时加
`{"slot":"arm_l","joint":"shoulder_l","deg":10,"hysteresis":6,"front":13,"back":24}`，验完清空）：

```
SW view=1 back=false
  ph=0.19 arm_l=8(-12°)   ← 往后摆，回落到静态 8
  ph=0.63 arm_l=8 ( +9°)   ← 还没到 10°，不动
  ph=0.69 arm_l=13(+12°)   ← 过阈值，切到 front 13
  ph=0.94 arm_l=13( +5°)   ← 已降到 5°，但迟滞 6 → 阈值 4，保持 13 不闪
==== 摆动层级全部符合规则 ====
```

阈值必须大于「手臂脱离躯干轮廓」的角度，否则会在还压着胸口时就切换，画面直接跳变。
默认留空，`swing_probe.gd` 见到空数组打印「跳过」并退出 0。

## 6. 无解清单（诚实版）

这些不是「还没做」，是**5 视图 + 镜像方案本身的上限**：

1. **分缝/疤/单侧护肩在镜像后换边**。`no_mirror` 只能让图案不翻，救不了「位置应该在另一侧」。
   要真解决只有一条路：这几个部件画满 8 列。
2. **斜向 45° 的装备必须单独画**。侧视翻转凑不出斜向（一条胳膊透视缩短、另一条伸展）。
3. **点头 / 弯腰在二维单轴下不存在**。只能靠美术加一档「低头视图」，或者放弃。
4. **举剑时会压脸**。除非给武器单开一个「举过头顶时降到头下面」的状态机槽位。
5. **交叉步穿模**。需要把 `hip_l/r` 的横向偏移也做成 per-view 曲线（增加 11 个参数）。

## 7. 如果要「完美八向」

按 FrameSprite 的账：静态图从 5 张变 8 张 = +60% 美术量；
而且这只是**静态图**，动画仍是逐方向单独做。按我们现在的 14 部件算，就是 112 张/角色（不含动作）。

现实做法是分档：
- **对称部件**（身体、腿、鞋、披风、后发）→ 5 张 + 镜像，够了；
- **有信息的部件**（脸、刘海、武器、盾、纹章）→ 该画 8 张就画 8 张；
- 这不是「要么全 5 要么全 8」，而是**逐槽位决定**——这才是 `PartDef.no_mirror` 存在的意义。
